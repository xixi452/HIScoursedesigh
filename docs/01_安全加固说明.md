# 安全加固说明（第 7 课 · Authenticate · Authorize · Audit）

> 基础代码：`04/his-mvp`（完整闭环：挂号 → 开方 → 收费 → 发药，含 verify_rules.py 实证脚本）。
> 本次在其上完成「认证 + 角色权限 + 安全」加固。角色：安全工程师。

---

## 一、做了什么

### 1. 认证（Authenticate）——密码绝不存明文

- 密码使用 **bcrypt 加盐哈希**（`security.hash_password` / `verify_password`）。
- 修复三处明文种子密码：`seed_schedules.py` 的 `seed_pwd`、`seed_prescription.py` / `seed_test_data.py` 的 `'x'`（改为 bcrypt，或统一走 `seed_users.py`）。
- 登录失败统一返回「用户名或密码错误」，不泄露账号是否存在；停用账号返回 403。

### 2. 授权（Authorize）——四种角色各司其职

- 登录签发 **JWT**（含 `sub` 用户 ID、`username`、`role`）。
- 依赖注入式鉴权：`get_current_user` + `require_permission(权限码)`，**没权限返回 403**。

| 接口 | 权限 | 允许角色 |
|---|---|---|
| `POST /api/register` 挂号 | `reg:create` | 挂号员 / 管理员 |
| `POST /api/prescriptions` 开方 | `prescription:create` | 医生 / 管理员 |
| `GET /api/drugs` 药品目录 | `prescription:read` | 医生 / 收费员 / 药师 / 管理员 |
| `POST /api/pay` 收费（FEFO 扣库存） | `billing:charge` | 收费员 / 管理员 |
| `POST /api/dispense` 发药确认 | `pharmacy:dispense` | 药师 / 管理员 |
| `GET /api/schedules` 号源查询 | `schedule:read` | 挂号员 / 管理员 |
| `GET /api/reg-orders/waiting` 候诊 | `reg:read` | 挂号员 / 医生 / 管理员 |

- **身份防伪造**：操作员身份一律从 JWT `sub` 派生，请求体里的 `operator_id/cashier_id/pharmacist_id` 已删除。

### 3. 审计与合规

- 登录更新 `last_login_at` 留痕。
- 金额服务端计算：开方按药品档案单价现算，收费按明细合计重算；请求模型 `PrescriptionItemIn` 本就**不含任何金额字段**（04 已具备，未改动）。
- 库存扣减在收费阶段按 FEFO 完成，扣减 SQL 带 `quantity >= ?` 兜底。

## 五、遗留风险与影响（上线前必须处理）

1. **JWT 密钥**：读环境变量 `HIS_JWT_SECRET`，仍有开发默认值；生产必须注入强随机密钥并轮换。
2. **`verify_rules.py` 影响**：该脚本是第 4 课「三条硬规则」的实证脚本，其请求体带 `operator_id/cashier_id` 且无鉴权头；加固后需补 JWT 才会通过。其覆盖的「事务/金额/库存/并发」四条硬规则在新代码中**依然成立**（见三层测试中的 409、库存不足 400、FEFO、幂等用例）。
3. **医生-号源级隔离**：开方目前为角色级校验，未绑定「本人号源」；数据模型 `sys_users` 与 `doctors` 尚未关联，下阶段补。
