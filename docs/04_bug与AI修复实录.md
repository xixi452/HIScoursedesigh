# bug 与 AI 修复实录（约 300 字）

安全加固初期，AI 生成的 04 版后端虽已有完整闭环，但隐患不少。最危险的是种子脚本里密码明文存 `seed_pwd`、`'x'`。我在提示词中明确要求「密码必须用 bcrypt 加盐哈希，明文存是事故」，AI 遂改用 bcrypt，并新增 `seed_users.py` 生成五角色账号。

其次，所有接口零鉴权，且操作员 ID 由前端请求体传入，任何人都能伪造身份越权。我要求 AI 补 JWT 鉴权中间件与 RBAC 依赖注入，把 `operator_id / cashier_id / pharmacist_id` 改为从令牌派生；实测收费员调开方接口由 200 变为 403。

跑测试时发现号源不足返回 400，与规范要求的 409 不符，AI 修改后通过。AI 扫描自身代码时，误报 CORS 过宽（实际已限定来源），又漏报「停用账号仍可登录」「医生可替他人开方」，均由我人工复核后补修或记遗留。

最终三层测试 50 条加 E2E 4 条全绿，覆盖率 84%。教训：AI 的清单不是结论，漏报误报都靠人把关。
