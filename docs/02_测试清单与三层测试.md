# 测试清单与三层测试（第 8 课 · 人工拟定，基于 04）

> 原则：测试清单（测什么：正常/边界/异常）由**人工拟定**；测试代码由 AI 编写、人工校验。
> 分层：单元测试（最多）→ API 测试 → E2E（最少，只覆盖主流程）。

---

## 一、人工拟定的测试清单（正常 / 边界 / 异常）

### 1. 认证与鉴权（登录 / JWT / RBAC）

| 类型 | 用例 | 预期 |
|---|---|---|
| 正常 | 正确用户名密码登录 | 200，返回 token + 角色 |
| 正常 | 携带 token 访问 `/api/me` | 200，返回当前用户 |
| 异常 | 错误密码登录 | 401 |
| 异常 | 不存在的用户登录 | 401，提示与错误密码**一致**（防枚举） |
| 异常 | 停用账号登录 | 403 |
| 异常 | 未携带 token 访问受保护接口 | 401 |
| 异常 | 伪造/过期 token | 401 |
| **异常** | **越权访问：收费员调开方接口** | **403** |
| 异常 | 收费员调挂号接口 / 医生调收费 / 发药 / 药师调收费 | 403 |

### 2. 挂号

| 类型 | 用例 | 预期 |
|---|---|---|
| 正常 | 挂号成功 | 201，返回挂号单号 + 排队号 + 费用 |
| 正常 | 挂号后号源余量 -1 | 余量 10→9 |
| **异常** | **挂号失败：号源不足（余量为 0）** | **409** |
| 异常 | 患者不存在 / 号源不存在 | 404 |

### 3. 开方

| 类型 | 用例 | 预期 |
|---|---|---|
| 正常 | 医生开方成功 | 201，金额由服务端按档案单价重算 |
| 边界 | 空处方（无明细） | 422 |
| 异常 | 停用药品 / 挂号单不存在 | 400 / 404 |
| 边界 | 单价/数量边界（0、负数） | 单元测试抛 ValueError |

### 4. 收费（04 版：收费阶段 FEFO 扣库存）

| 类型 | 用例 | 预期 |
|---|---|---|
| 正常 | 收费成功 | 200，生成收费单，金额=明细合计 |
| 正常 | FEFO：先扣近效期批次 | 扣最早批次 `AMX202701` |
| 边界 | 相同 request_id 重复提交 | 幂等，返回同一张单 |
| 异常 | 已收费处方再次收费 | 400 |
| **异常** | **库存不足收费** | **400，整单回滚，库存不变** |

### 5. 发药（04 版：确认发药）

| 类型 | 用例 | 预期 |
|---|---|---|
| 正常 | 发药成功 | 200，处方置「已发药」 |
| 异常 | 未收费处方发药 | 400 |

### 6. 单元测试（纯函数，数量最多）

| 函数 | 正常 / 边界 / 异常 |
|---|---|
| 划价 `compute_line_amount` | 正常 2×2000=4000；边界 数量=0、单价=0；异常 负数 |
| FEFO `allocate_fefo` | 正常顺序扣；边界 需要量=0；异常 库存不足 |
| 排队号 `next_queue_no` | 正常 0→1；异常 负数 |
| 密码哈希 | 正常校验通过；异常 错误密码 / 非法哈希 / 加盐不同 |

## 三、E2E 说明

- E2E 采用 **Playwright `request` 上下文驱动真实运行中的后端**（uvicorn + 真实 SQLite），覆盖「登录→挂号→开方→收费→发药」主流程与 401/403/409。
- 浏览器级 UI E2E 依赖前端登录页；本次已补前端登录（`frontend` 可正常 `npm run build`），UI 级 E2E 列为下阶段加分项，避免测试因 UI 脆弱而不稳定。
