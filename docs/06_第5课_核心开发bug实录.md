# 第 5 课 · 最难 bug 与 AI 修复实录（约 300 字）

最难的是并发挂号超卖。开发挂号接口时，AI 最初写成「先 SELECT 号源余量 → 再 UPDATE 减一 → 再 INSERT 挂号单」，单线程测试全绿；但并发下两个挂号员同时抢最后一个号，两个都读到 remaining=1，结果两人都成功，号源被扣成负数。

我按「报错三件套」给 AI 描述：@backend/routers/registration.py 贴代码 + 描述现象「并发 20 人抢 1 个号有 2 人成功」+ 期望「恰好 1 人成功、其余 409」。AI 改写成：`BEGIN IMMEDIATE` 立刻拿写锁，扣号源改成条件更新 `UPDATE ... WHERE remaining_count > 0`，受影响行数为 0 就回滚返回 409；排队号改成事务内 `COUNT+1` 并加 `(schedule_id, queue_no)` 唯一约束双保险。

修后用 8 线程并发实测：恰好 1 成功 7 失败，remaining=0，无重复排队号。学到：并发问题 AI 默认不会想到，必须我在提示词里点名「事务 + 条件更新 + 唯一约束」，验收时主动压边界场景，别只走正常路径。
