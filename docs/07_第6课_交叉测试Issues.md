# 第 6 课 · 交叉测试 Issues（药房收费闭环）

> 按「复现步骤 / 期望行为 / 实际行为」格式，共 4 条（≥3 条达标）。

## Issue #1：收费采信前端传价，患者可改价

- **复现步骤**：开方后，把收费请求体里的金额字段篡改为 1 分，调 `POST /api/pay`。
- **期望行为**：金额由后端按药品档案单价重算，前端传价一律忽略。
- **实际行为**：初版直接采信前端金额，等于「患者可自己改价」。（已修复：`payment.py` 用 `SUM(amount_cents)` 后端重算，请求体不含金额字段）

## Issue #2：库存不足未整单回滚

- **复现步骤**：造一张含两种药品的处方，其中一种库存不足，执行收费。
- **期望行为**：返回 400「库存不足」，整单回滚，两种药品库存都不变、无新增账单。
- **实际行为**：初版逐条扣减，先扣了第一种，第二种失败后回滚不彻底。（已修复：单事务内 FEFO 逐条扣，任一条失败统一 `rollback`；`drug_stocks.quantity >= 0` CHECK 兜底）

## Issue #3：重复收费（幂等失效）

- **复现步骤**：同一处方用相同 `request_id` 连续提交两次收费。
- **期望行为**：只生成一张账单，第二次返回同一账单，不重复扣费/扣库存。
- **实际行为**：初版无幂等，重复提交重复扣费。（已修复：`bills.request_id` 唯一约束 + 命中直接返回）

## Issue #4：未收费处方也能发药

- **复现步骤**：开方后不收费，直接调 `POST /api/dispense`。
- **期望行为**：返回 400「处方当前状态不可发药」。
- **实际行为**：初版未校验状态，未收费也能发药出库。（已修复：`dispense.py` 校验 `status='已收费'`，事务内复检）
