## 1. 项目目标

在 5 周核心开发期内交付一个**可运行、可演示、可验收**的门诊闭环 MVP（第 12 课答辩前完成联调与材料）：

1. 跑通“挂号（扣号源）→ 就诊 → 开方 → 收费（算金额）→ 发药（扣批次库存）”一条主线。
2. 做到“麻雀虽小，五脏俱全”：有登录/角色/权限，有号源、库存、费用三条业务规则，有事务与身份证脱敏。
3. 不追求完整 HIS，只按《医院信息系统基本功能规范》实现 3 个分系统的部分功能，功能可少，骨架不能缺。

## 2. 范围

### 2.1 做（In Scope）

| 分系统/模块 | 本次范围 | 关键交付 |
|---|---|---|
| 门诊挂号 | 排班号源、号源查询、现场挂号、挂号费（P1）、退号、候诊队列、挂号日报 | 号源不超卖；挂号单/排队号；退号回滚 |
| 门诊医生工作站（子集） | 接诊、患者信息、门诊病历、开方、处方明细、金额计算、提交、收费前修改/作废、处方打印、工作量 | 处方与挂号单关联；金额后端重算 |
| 门诊药房（含划价收费） | 待收费队列、划价、收费、收费单、未发药退费、待发药审核、发药、FEFO 批次、发药记录、未拆封整单退药（同步退费）、入库、库存预警、日报 | 收费后发药；扣批次库存；效期/状态校验 |
| 公共支撑 | 登录/登出、用户管理、RBAC、审计日志、科室/医生/药品基础数据、患者建档查重、身份证脱敏、密码哈希 | 权限三件套；关键操作留痕；无明文身份证 |

### 2.2 不做（Out of Scope）

| 不做项 | 理由 |
|---|---|
| 住院、手术、体检、病案、电子病历归档 | 非 A 门诊线；超出 3 个分系统 |
| 预约挂号、叫号大屏/语音、挂号发票打印、爽约黑名单 | 需要额外渠道/硬件/票据系统；MVP 只做现场挂号与队列查询 |
| 检验检查（LIS/PACS）、合理用药/配伍禁忌、病历模板/知识库 | 依赖外部系统或知识库；MVP 只做必填/库存/金额校验 |
| 医保实时结算、在线支付、电子发票 | 需要医保/支付/税控接口；PPT 明确在线支付 MVP 不加 |
| 盘点/调拨、采购/供应商、麻精药品、静配/代煎 | 供应链与特殊药事管理；超出课程范围 |
| 多院区、多挂号渠道、患者 APP/自助机 | 单院区、工作人员 Web 端；多院区涉及数据隔离 |
| 部分退费、拆封退药、跨批次退药 | MVP 只做整单退费、未拆封整单退药、原批次回补并同步退费；复杂场景后续扩展 |

> 范围冻结：以上“不做”项在 MVP 期间不接单；新想法统一进 backlog，第 9 课部署后由组内投票决定是否做扩展。

## 3. 用户与权限

| 角色 | 主要权限 | 明确禁止 |
|---|---|---|
| 挂号员 | 患者建档、查号源、挂号、退号、挂号日报 | 开方、收费、发药、改库存 |
| 医生 | 接诊、写病历、开方、提交、收费前修改/作废、查历史 | 挂号、收费、退费、发药、改库存 |
| 收费员 | 查待收费处方、划价、收费、未发药退费、收费日报 | 开方、发药、改库存、改处方 |
| 药师 | 待发药审核、发药、退药、入库、库存查询/预警、发药日报 | 开方、收费、退费、改患者信息 |
| 管理员 | 用户/角色/权限、科室/医生/药品基础数据、审计日志 | 不直接参与日常业务（避免既当裁判又当运动员） |

权限模型：用户 → 角色 → 权限；后端每个写接口都要校验权限，不能只靠前端隐藏菜单。

## 4. 核心业务规则（验收底线）

1. **号源就是库存**：挂号事务内 `remaining_count` 减 1，条件更新 `remaining_count > 0`；退号加 1；并发不得超卖。
2. **排队号**：同一号源内按已挂号数递增，`(schedule_id, queue_no)` 唯一；不能因并发产生重复排队号。
3. **费用后端算**：处方总额 = Σ(数量 × 单价快照)；收费金额以服务端重算为准，前端传值一律不信任；金额用“分”存整数，不用浮点数。
4. **收费后才发药**：处方状态必须为“已收费”才能发药；发药事务内按 FEFO 扣批次库存，任一批次不足整单回滚。
5. **效期与状态**：过期、冻结、召回批次不可发药；发药时同时校验 `expiry_date >= 今天` 和 `status = 正常`。
6. **退路完整**：退号回滚号源，若已收挂号费则同步退费；未发药可退费；已发药仅未拆封可整单退药，回补原批次并同步退费；已收费处方不能直接改。
7. **身份证脱敏**：展示 `110101********1234`；库内只存脱敏串、哈希、后四位，不存明文；日志/导出同样脱敏。
8. **关键操作留痕**：登录、挂号、退号、收费、退费、发药、退药、库存变更、权限变更写审计日志。

### 事务清单

| 事务 | 必须一起成功/回滚的步骤 |
|---|---|
| 挂号 | 条件扣号源 → 生成挂号单 → 生成排队号 → 生成挂号费收费单 |
| 退号 | 校验状态 → 挂号单置退号 → 号源加 1 → 若已收挂号费，收费单置已退费 |
| 收费 | 校验处方待收费 → 后端重算金额 → 生成收费单 → 处方置已收费 |
| 发药 | 校验处方已收费 → 按 FEFO 逐批扣库存 → 写发药记录 → 处方置已发药 |
| 退药 | 校验已发药/未拆封/整单 → 回补原批次 → 写退药记录 → 处方置已退药 → 收费单置已退费 |

## 5. 非功能要求

| 维度 | 要求 | 验收方式 |
|---|---|---|
| 性能 | 单机演示，50 并发以内；核心查询/写入 P95 < 500ms；挂号/发药事务 < 1s | 用脚本压测最后 1 个号源、最后 1 个批次 |
| 安全 | 密码 bcrypt/argon2；登录会话/JWT；RBAC 后端校验；参数化 SQL；防 SQL 注入/XSS/CSRF；错误信息不泄露账号是否存在 | 越权用例、注入用例、弱密码用例 |
| 数据 | SQLite 开启外键与 WAL；金额用分；状态用 CHECK；唯一约束防重；每日备份；关键事务 `BEGIN IMMEDIATE` | 断点/回滚测试；重复提交测试；备份恢复演练 |
| 合规 | 身份证脱敏显示、哈希查重、不存明文；日志脱敏；最小必要采集；演示数据使用虚构号码 | 全库/日志检索不到明文；页面截图核对 |
| 兼容 | Chrome/Edge 最新版；1366×768 及以上；中文界面 | 演示机实机检查 |
| 可用性 | 关键操作有确认/错误提示；状态用中文；空数据有引导；危险操作二次确认 | 组内走查 + 用户试用 |

## 6. 交付物与验收主线

### 6.1 交付物

1. 《功能点清单》（含实现/不实现及理由、验收标准、状态机）。
2. 《项目范围说明书》（本文件）。
3. ER 图（Mermaid）+ 数据字典 + `04_schema.sql`。
4. 前后端骨架仓库：`npm run dev` 与 `uvicorn` 可跑；Git 提交记录完整。
5. 演示脚本、测试用例、README（启动方式、账号、演示数据说明）。

### 6.2 验收主线（按顺序演示，缺一步不算通过）

1. 挂号员登录 → 选号源 → 挂号成功 → 号源减 1、生成排队号。
2. 医生登录 → 接诊 → 写病历/诊断 → 开处方 → 提交。
3. 收费员登录 → 打开待收费处方 → 收费 → 生成收费单。
4. 药师登录 → 待发药队列 → 按 FEFO 发药 → 批次库存扣减、生成发药记录。
5. 反例：号源为 0 时挂号被拦截；未收费发药被拦截；库存不足整单回滚；身份证页面/日志无明文。
